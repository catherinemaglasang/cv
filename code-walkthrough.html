01

The Agentic Chat Loop

TypeScript · LoopBack 4 API · newsletter-chat.service.ts

This is the heart of the entire system. When a user sends a message, the chat service orchestrates a multi-turn conversation with Claude (via AWS Bedrock). The AI can call "tools" — functions that do things like research a website, generate templates, or replace text. After each tool runs, the result goes back to the AI for the next step. This loop can run up to 10 turns in a single user message.

What's an "agentic loop"? Think of it like a conversation where the AI is an employee who can ask questions and use tools. You say "generate a newsletter about dental hygiene." The AI thinks, then calls a tool to generate templates. The tool returns results. The AI looks at the results, then responds to you. If it needs more steps (e.g., set up the sender first), it calls another tool. That loop of "think → act → observe → think again" is the agentic loop.

The key optimization: fast-path exits. When the AI calls a tool that produces a visual result (like replacing text), we skip the second AI call entirely. Why ask the AI to say "Done!" when the user can already see the change? This cuts response time from ~4 seconds to under 200ms.

Why this matters: Every AI call costs money and takes 3–5 seconds. By detecting when the result is already visible to the user, we skip the AI entirely. Over hundreds of edits per day, this saves real time and real cost. The system also handles "cascading" — if you change a heading, related paragraphs and button text auto-update in one shot.

Real-Time SSE Streaming

TypeScript · LoopBack 4 API · newsletter-chat.service.ts

Instead of waiting for the AI to finish its entire response before showing anything, we stream every word as it's generated — character by character, in real time. This uses a web technology called Server-Sent Events (SSE). The AI's response flows through 20+ event types: text chunks, tool calls, template updates, research results, session IDs, and more.

What's SSE? Imagine a phone call where one person talks and the other listens. SSE is like that — the server keeps an open connection and pushes updates to the browser as they happen. Unlike a regular web request where you ask and wait for the full answer, SSE lets you see the answer being typed out in real time (like ChatGPT's typing effect).
📄 src/controllers/newsletter.controller.ts — Lines 375–460
@post('/api/newsletter/chat', { responses: { '200': STREAM_RESPONSE } })
async chat(
  @requestBody() req: { companyId: string; message: {role: string; content: string}; ... },
  @inject(RestBindings.Http.RESPONSE) response: Response,
): Promise<void> {
  const logger = new CustomLogger(req.companyId || 'newsletter-chat');

  // Security: Sanitize companyId (prevent path traversal)
  const companyIdValidation = sanitizeCompanyId(req.companyId);
  if (!companyIdValidation.valid) {
    response.status(400).send({error: 'Invalid company identifier'});
    return;
  }
  const safeCompanyId = companyIdValidation.sanitized!;

  // Security: Rate limiting
  const rateLimitResult = checkRateLimit(safeCompanyId, {
    maxRequestsPerMinute: 10, maxGenerationsPerSession: 50,
  });
  if (!rateLimitResult.allowed) {
    response.status(429).send({
      error: `Rate limit exceeded. Try again in ${rateLimitResult.retryAfter} seconds.`
    });
    return;
  }

  // Set SSE headers — X-Accel-Buffering: no prevents nginx from buffering the stream
  response.setHeader('Content-Type', 'text/event-stream; charset=utf-8');
  response.setHeader('Cache-Control', 'no-cache, no-transform');
  response.setHeader('Connection', 'keep-alive');
  response.setHeader('X-Accel-Buffering', 'no');

  // Security: Redact message content from logs (may contain PII)
  logger.info(`chat, companyId: ${safeCompanyId}, message length: ${req.message.content.length}`);

  // Stream events to the browser as they happen
  await this.chatService.chat({...req, companyId: safeCompanyId}, {
    onTextChunk:     (chunk) => response.write(`data: ${JSON.stringify({type: 'content', text: chunk})}\n\n`),
    onToolUse:       (tool)  => response.write(`data: ${JSON.stringify({type: 'tool_use', tool: {...}})}\n\n`),
    onTemplatesReady:(data)  => response.write(`data: ${JSON.stringify({type: 'templates_ready', data})}\n\n`),
    onSessionReady:  (sid)   => response.write(`data: ${JSON.stringify({type: 'session_ready', sessionId: sid})}\n\n`),
    onGenerationStarted: (d) => response.write(`data: ${JSON.stringify({type: 'generation_started', ...d})}\n\n`),
    onResearchReady: (data)  => response.write(`data: ${JSON.stringify({type: 'research_ready', data})}\n\n`),
    onBrandAnalysisReady: (d)=> response.write(`data: ${JSON.stringify({type: 'brand_analysis_ready', data: d})}\n\n`),
    onError:         (error) => response.write(`data: ${JSON.stringify({
      type: 'error', message: 'Something went wrong. Please try again.'  // Never expose raw errors
    })}\n\n`),
    onComplete:      (result)=> response.write(`data: ${JSON.stringify({type: 'done', ...result})}\n\n`),
  });
  response.end();
}
Why this matters: The callback-based architecture keeps every SSE event structured and typed. Security is baked in at every layer: companyId sanitization, rate limiting, and error sanitization all happen before any AI logic runs. Error messages never leak internal details — the user sees "Something went wrong" while the full stack trace is logged server-side.

Fast Refinement Engine

TypeScript · LoopBack 4 API · newsletter.tools.ts

When a user says "change the background to blue" or "use Roboto font," why call an expensive AI model? This engine handles color swaps, font changes, text replacements, and spacing adjustments entirely with code — no AI needed. It walks the MJML JSON tree, finds the right elements, and makes the change programmatically.

What's MJML? Email clients (Gmail, Outlook, etc.) all render HTML differently. MJML is a special markup language designed for emails — you write simple MJML and it compiles into the ugly, complex HTML that works everywhere. Our system stores templates as MJML JSON trees, which are easy to manipulate programmatically.
📄 src/utils/newsletter.tools.ts — Lines 1144–1281
/**
 * Attempt a fast programmatic refinement. Returns {mjmlJson, html, label} or null.
 * Handles: color swaps, font swaps, text replacements, text color changes.
 */
private tryFastRefinement(
  mjmlJson: any, instruction: string
): {mjmlJson: any; html: string; label: string} | null {
  const lower = instruction.toLowerCase();

  // 1) Color swap — hex codes + color keywords
  const colorResult = this.tryColorSwap(mjmlJson, instruction, lower);
  if (colorResult) return colorResult;

  // 2) Font swap — "change font to X", "use X font"
  const fontResult = this.tryFontSwap(mjmlJson, instruction, lower);
  if (fontResult) return fontResult;

  // 3) Text replacement — "replace X with Y", "change header to Y"
  const textResult = this.tryTextReplace(mjmlJson, instruction, lower);
  if (textResult) return textResult;

  return null;  // Not a simple change — fall back to AI
}

/** Font swap: "change font to Roboto", "use Georgia font", "switch to Arial" */
private tryFontSwap(mjmlJson: any, instruction: string, lower: string):
  {mjmlJson: any; html: string; label: string} | null {

  const fontKeywords = ['font', 'typeface', 'typography'];
  if (!fontKeywords.some(k => lower.includes(k))) return null;

  // Bail on structural changes — these need the AI
  const structuralKeywords = ['layout', 'section', 'column', 'add', 'remove', 'image'];
  if (structuralKeywords.some(k => lower.includes(k))) return null;

  // Extract target font name with multiple regex patterns
  const fontMatch = instruction.match(
    /(?:to|use|switch\s+to)\s+([A-Z][a-zA-Z\s]+?)(?:\s+(?:font|with|as|and|for)\b|\s*$|\s*,)/i
  ) || instruction.match(
    /([A-Z][a-zA-Z\s]+?)\s+font\b/i
  );
  if (!fontMatch) return null;

  const newFont = fontMatch[1].trim();
  if (newFont.split(/\s+/).length > 3 || newFont.length > 30) return null;

  // Detect scope: "change header font" vs "change all fonts"
  const scope = this.detectFontScope(lower);  // 'all' | 'header' | 'paragraph' | 'button'

  this.logger.info(`Fast font swap: "${newFont}" (scope: ${scope})`);
  const updatedJson = JSON.parse(JSON.stringify(mjmlJson));
  this.swapFontInJson(updatedJson, newFont, scope);
  const html = this.templateGenerator.renderJsonToHtml(updatedJson);
  return {mjmlJson: updatedJson, html, label: `font swap (${scope})`};
}
Why this matters: AI calls cost ~$0.005 each and take 3–8 seconds. The fast refinement engine handles ~20% of all edit requests without touching the AI at all. Average response time drops from ~5 seconds to under 200ms. The 3-tier approach (color → font → text) catches the most common edits, and anything complex gracefully falls back to the AI.

Security Hardening Layer

TypeScript · LoopBack 4 API · security.validator.ts

This centralized module handles 12 categories of web vulnerabilities in one file. Every external input passes through these validators before reaching any business logic.

What's SSRF? Server-Side Request Forgery. Imagine a feature where you paste a URL and the server fetches it for you (like our website scraper). An attacker could paste http://169.254.169.254/ — a special address that only works from inside AWS. That address returns secret credentials. SSRF protection blocks requests to internal/private IP addresses, even if an attacker uses DNS tricks to disguise them.
📄 src/utils/security.validator.ts — Lines 22–114
/**
 * Sanitize companyId to prevent path traversal and S3 key injection.
 * Only alphanumeric chars, hyphens, underscores allowed (no path separators).
 */
export function sanitizeCompanyId(companyId: string):
  {valid: boolean; sanitized?: string; error?: string} {
  if (!companyId || typeof companyId !== 'string') {
    return {valid: false, error: 'Company ID is required'};
  }
  const trimmed = companyId.trim();

  // Check for path traversal attempts: ../../etc/passwd
  if (trimmed.includes('..') || trimmed.includes('/') || trimmed.includes('\\')) {
    logger.warn(`Path traversal attempt detected in companyId: ${companyId}`);
    return {valid: false, error: 'Invalid company ID format'};
  }

  // Strict allowlist: only safe characters
  const sanitized = trimmed.replace(/[^a-zA-Z0-9_-]/g, '');
  if (sanitized.length === 0 || sanitized.length > 100) {
    return {valid: false, error: 'Invalid company ID format'};
  }
  return {valid: true, sanitized};
}

/**
 * Validate URL to prevent SSRF attacks.
 * Blocks: AWS metadata, localhost, private IPs (RFC 1918).
 * Resolves DNS BEFORE making the request to prevent DNS rebinding.
 */
export async function validateUrlForSSRF(url: string):
  Promise<{valid: boolean; error?: string; resolvedIps?: string[]}> {
  try {
    const parsed = new URL(url);

    // Only HTTP/HTTPS
    if (!['http:', 'https:'].includes(parsed.protocol)) {
      return {valid: false, error: 'Only HTTP/HTTPS URLs are allowed'};
    }

    // Block localhost variants
    const hostname = parsed.hostname.toLowerCase();
    if (['localhost', '127.0.0.1', '0.0.0.0', '[::1]'].includes(hostname)) {
      logger.warn(`SSRF attempt blocked: localhost URL ${url}`);
      return {valid: false, error: 'Internal URLs are not allowed'};
    }

    // Resolve DNS to actual IPs BEFORE making the request
    let ips: string[];
    try {
      ips = await resolveDns(hostname);
    } catch {
      return {valid: true};  // DNS failed — let HTTP client handle it
    }

    // Block any resolved IP that's private/internal
    for (const ip of ips) {
      if (isPrivateIP(ip)) {
        logger.warn(`SSRF attempt blocked: ${url} resolves to internal IP ${ip}`);
        return {valid: false, error: 'URLs resolving to internal addresses are not allowed'};
      }
    }

    return {valid: true, resolvedIps: ips};
  } catch (err: any) {
    return {valid: false, error: 'Invalid URL format'};
  }
}
Why this matters: This single file prevents 6+ attack types: SSRF (accessing internal cloud infrastructure), path traversal (reading files outside the allowed directory), S3 key injection (accessing other companies' data), file upload attacks (disguised executables), HTML injection, and error information leakage. The DNS pre-resolution prevents "DNS rebinding" — a sophisticated attack where a domain resolves to a safe IP initially but switches to an internal IP on the actual request.

Background Generation & Polling

TypeScript · LoopBack 4 API · generation-job-store.ts

Generating 3 newsletter templates takes 40–90 seconds. If we kept the HTTP connection open that long, nginx would kill it with a 504 timeout. The solution: start the job in the background, give the browser a job ID, and let it poll for results.

What's polling? Like checking the oven every few minutes. The browser asks "is my job done?" every 3 seconds. When the server says "yes, here are your templates," the browser stops asking and shows the results. This is simpler and more reliable than keeping a long connection open.
📄 src/utils/generation-job-store.ts — Lines 1–84
// ─── In-Memory Generation Job Store ─────────────────────────────────────
// Module-level Map that survives across HTTP requests (lives in Node module scope).
// Tracks background newsletter generation jobs so the frontend can poll for results.

export interface GenerationJob {
  jobId: string;              // "gen-{companyId}-{timestamp}"
  companyId: string;
  sessionId: string;
  status: 'generating' | 'complete' | 'failed';
  startedAt: number;
  completedAt?: number;
  templates?: any[];          // Full template array on completion
  error?: string;
}

const jobs = new Map<string, GenerationJob>();
const MAX_JOBS = 100;
const JOB_TTL_MS = 10 * 60 * 1000;  // 10 minutes

/** Create a new generation job. */
export function createJob(jobId: string, companyId: string, sessionId: string): GenerationJob {
  if (jobs.size >= MAX_JOBS) evictOldestCompleted();  // Prevent memory leak
  const job: GenerationJob = {
    jobId, companyId, sessionId, status: 'generating', startedAt: Date.now(),
  };
  jobs.set(jobId, job);
  return job;
}

/** Mark a job as complete with template results. */
export function completeJob(jobId: string, templates: any[]): void {
  const job = jobs.get(jobId);
  if (!job) return;
  job.status = 'complete';
  job.completedAt = Date.now();
  job.templates = templates;
}

/** Find any active job for a company (prevents double-generation). */
export function getActiveJobForCompany(companyId: string): GenerationJob | undefined {
  for (const job of jobs.values()) {
    if (job.companyId === companyId && job.status === 'generating') return job;
  }
  return undefined;
}

📄 newsletter-generator.blade.php — Lines 2516–2596 (Frontend)
function startGenerationPolling(jobId) {
    stopGenerationPolling();
    let pollCount = 0;
    let consecutiveErrors = 0;
    const MAX_POLLS = 60;              // 3 minutes at 3s interval
    const MAX_CONSECUTIVE_ERRORS = 10;  // stop after 10 straight failures

    generationPollTimer = setInterval(async () => {
        pollCount++;
        if (pollCount > MAX_POLLS) {
            stopGenerationPolling();
            hideGeneratingOverlay();
            addMessage('assistant', 'Generation is taking longer than expected. Please try again.');
            return;
        }
        try {
            const resp = await fetch(GENERATION_STATUS_URL + '?jobId=' + encodeURIComponent(jobId), {
                headers: {'X-CSRF-TOKEN': CSRF_TOKEN, 'Accept': 'application/json'},
                credentials: 'same-origin',
            });

            if (!resp.ok) {
                consecutiveErrors++;
                if (resp.status === 401 || resp.status === 419) {
                    // Auth or CSRF expired — stop immediately
                    stopGenerationPolling();
                    addMessage('assistant', 'Session expired. Please refresh the page.');
                    return;
                }
                if (consecutiveErrors >= MAX_CONSECUTIVE_ERRORS) {
                    stopGenerationPolling();
                    addMessage('assistant', 'Unable to check progress. Please refresh.');
                    return;
                }
                return; // Keep polling — might recover
            }

            consecutiveErrors = 0;  // Reset on success
            const json = await resp.json();

            if (json.status === 'complete') {
                stopGenerationPolling();
                hideGeneratingOverlay();
                if (json.templates && Array.isArray(json.templates)) {
                    renderTemplates(json.templates);
                }
            }
        } catch (err) { consecutiveErrors++; }
    }, 3000);
}
Why this matters: The getActiveJobForCompany() guard prevents a critical bug: if the AI accidentally calls generate_newsletter twice, the second call finds the existing job and returns it instead of starting a duplicate. The frontend polling has 3 layers of protection: max poll limit (timeout), consecutive error tracking (bad server), and auth status detection (expired session). The in-memory store auto-evicts old jobs so the server never runs out of memory.

Click-to-Edit System

JavaScript · Laravel Blade · newsletter-generator.blade.php

Users can click on any image or text in the live email preview to edit it. This required a click-event system that works inside iframes — the email preview lives in an iframe to isolate its styles from the main page. Each mode (image, text, button) is mutually exclusive and uses named event handlers for clean attach/detach.

📄 newsletter-generator.blade.php — Lines 3065–3162
// ─── Image Click-to-Edit ──────────────────────────────────
function attachImageClickHandlers(iframe) {
    if (!imageClickModeActive) return;
    if (!iframe || !iframe.contentDocument) return;
    const imgs = iframe.contentDocument.querySelectorAll('img');

    let visibleIndex = 0;
    imgs.forEach(function(img) {
        // Skip tiny images (icons, spacers) — only make real images clickable
        if (img.naturalWidth < 50 && img.width < 50) return;

        const currentIndex = visibleIndex;
        img.style.cursor = 'pointer';
        img.style.transition = 'outline 0.2s';

        // Named handlers for clean detach later
        img._imgEditEnter = function() { img.style.outline = '3px dashed #3BA9C2'; };
        img._imgEditLeave = function() { img.style.outline = ''; };
        img._imgEditClick = function() { onImageClicked(currentIndex, img, iframe); };

        img.addEventListener('mouseenter', img._imgEditEnter);
        img.addEventListener('mouseleave', img._imgEditLeave);
        img.addEventListener('click', img._imgEditClick);
        visibleIndex++;
    });
}

// ─── Text Click-to-Edit ──────────────────────────────────
function attachTextClickHandlers(iframe) {
    if (!textClickModeActive) return;
    if (!iframe || !iframe.contentDocument) return;

    // Find elements by CSS class identifier (e.g. "identifier-mj-text-5")
    // This ID maps directly to the backend's MJML JSON tree position
    var textEls = iframe.contentDocument.querySelectorAll('[class*="identifier-mj-text-"]');

    textEls.forEach(function(el) {
        var match = el.className.match(/identifier-mj-text-(\d+)/);
        if (!match) return;
        var textIndex = parseInt(match[1], 10);

        el.style.cursor = 'pointer';
        el._textEditEnter = function() { el.style.outline = '2px dashed #3BA9C2'; };
        el._textEditLeave = function() { el.style.outline = ''; };
        el._textEditClick = function() { onTextClicked(textIndex, el, iframe); };

        el.addEventListener('mouseenter', el._textEditEnter);
        el.addEventListener('mouseleave', el._textEditLeave);
        el.addEventListener('click', el._textEditClick);
    });
}
Why this matters: The named handler pattern (img._imgEditEnter) solves a common JavaScript bug: if you use anonymous functions with addEventListener, you can never remove them later with removeEventListener. By storing each handler as a property on the element itself, we can cleanly detach all handlers when switching modes — no memory leaks, no ghost event handlers. The CSS class identifier system (identifier-mj-text-5) bridges the visual DOM and the backend's JSON tree, making it possible to map a click in the preview directly to the right node in the MJML data structure.

Dentrix Ascend Data Pipeline

Python · AWS Step Functions + Lambda + SQS · Jarvis Analytics

At Jarvis Analytics, I built a data sync pipeline that pulls dental practice data from the Dentrix Ascend cloud platform into our analytics database. The system syncs 40+ API endpoints into 51 database tables, handling pagination, retries, rate limiting, and incremental updates.

What's a data pipeline? Dental practices use software (like Dentrix Ascend) to manage patients, appointments, billing, etc. That data lives in Dentrix's cloud. def get_page_size(default_pagesize=500, previous_pagesize=None,
                  retry_count=0, recovery_count=0):
    """
    Adaptive page sizing: shrinks on failure, grows on recovery.
    - No retries: use default (500)
    - Recovering: slowly increase (50% increments back to default)
    - Retrying: halve each time (exponential backoff on page size)
    - 5+ retries: drop to 1 record at a time (last resort)
    """
    if previous_pagesize is None:
        return default_pagesize
    elif retry_count == 0 and recovery_count == 0 and previous_pagesize < default_pagesize:
        # Recovering — increase by 50% each success, capped at default
        return min(int(previous_pagesize + max(previous_pagesize * 0.5, 1)), default_pagesize)
    elif retry_count == 0:
        return previous_pagesize
    elif retry_count >= 5:
        return 1  # Last resort: one record at a time
    else:
        # Exponential backoff: halve page size on each retry
        return max(int(previous_pagesize / (2 * retry_count)), 1)

Real-Time Stream Consumer

Python · RabbitMQ + SQS · Jarvis Analytics

Beyond the batch sync, the pipeline also supports real-time streaming. When a dental practice creates a new appointment or records a payment in Dentrix Ascend, that change flows through RabbitMQ (a message queue) to our consumer, which routes it to AWS SQS for processing.

What's a message queue? Think of it like a post office. When something happens in the dental software (new patient created, appointment booked), it drops a "letter" into the queue. Our consumer picks up those letters and processes them. This decoupling means the dental software doesn't have to wait for our system — it just drops the message and moves on. If our system is busy, messages wait in the queue until we're ready.
📄 scripts/src/streams.py — Lines 18–79
async def on_message(message: AbstractIncomingMessage) -> None:
    async with message.process():
        # Parse routing key: "orgId.locationId.domainType.operation"
        [organization_id, location_id, domain_type, operation] = \
            message.routing_key.split('.')

        message_body = json.loads(str(message.body, 'utf-8'))
        payload = message_body['payload']
        record_id = message_body['id']

        # Route to correct SQS queue (production vs staging)
        test_orgs = ["5fa5bce5471d910c1b33e320"]
        sync_env = config('SYNC_ENVIRONMENT', default='prod')
        sqs_queue = config('SQS_QUEUE_STAGE' if organization_id in test_orgs
                          or sync_env == 'stage' else 'SQS_QUEUE')

        # Clean oversized nested data (e.g. PatientV1.referredPatients)
        if domain_type == "PatientV1" and 'referredPatients' in payload:
            del payload['referredPatients']

        # Build SQS event and send with deduplication
        sqs = boto3.client('sqs')
        event = {
            'producer': False,
            'organization_id': organization_id,
            'payload': payload,
            'id': record_id,
            'operation': operation,       # CREATE, UPDATE, or DELETE
            'domain_type': domain_type,   # PatientV1, Transaction, etc.
        }

        # Deduplication: hash the content to prevent duplicate processing
        if operation == 'DELETE':
            dedup_id = f"{organization_id}-{domain_type}-DELETE-{record_id}"
        else:
            dedup_id = hashlib.md5(
                (operation + json.dumps(payload)).encode('utf-8')
            ).hexdigest()

        sqs.send_message(
            QueueUrl=sqs_queue,
            MessageBody=json.dumps(event),
            MessageDeduplicationId=dedup_id,
            # Group by org + domain + ID modulo (preserves ordering within entity)
            MessageGroupId=f"{organization_id}{domain_type}{int(record_id) % 9}"
        )
Why this matters: The deduplication strategy is critical — RabbitMQ can deliver the same message twice under network issues. The MD5 hash of the payload ensures we never process a duplicate. The MessageGroupId with modulo 9 is a clever balancing act: it keeps related records ordered (same entity type from same org) while spreading load across 9 SQS partitions for parallelism.

Matchback Lead Tracking

SQL · MySQL Stored Procedures · Jarvis Analytics

Marketing agencies spend thousands on Google Ads, Facebook campaigns, and SEO to get new patients to dental practices. But did those campaigns actually work? Matchback answers that question: it links marketing leads (form submissions, phone calls) to actual patient visits in the dental practice's system — proving ROI.

What's a stored procedure? A stored procedure is a pre-written SQL program that lives inside the database. Instead of writing a complex query every time, you "call" the procedure with parameters (like a patient's name and email) and it runs the full matching logic internally. Think of it like a function, but it runs inside the database engine itself — much faster than sending multiple queries from an external application.
📄 stored-procs/matchback/matchback_v5.sql — Lead-to-Patient matching
/*
  Matchback v5 — Link marketing leads to completed dental appointments.

  Matching strategy:
    FORMS (website submissions):
      1. Email → 100% confidence match
      2. Last name + Zip code → 100% (if location matches)
      3. Phone → 100% confidence match

    CALLS (phone leads):
      1. Phone → 100% confidence match

  Works across 4 PMS platforms:
    EagleSoft, OpenDental, Dentrix Ascend, Denticon

  Returns: all patients with completed appointments within 60 days
           of the lead date (first appointment only per patient).
*/

  command TEXT,        -- 'forms' or 'calls'
  lname TEXT,          -- lead's last name
  fname TEXT,          -- lead's first name
  email TEXT,          -- lead's email (blank for calls)
  phone TEXT,          -- lead's phone
  zip TEXT,            -- lead's zip code (blank for calls)

  `lead_date` TEXT,    -- when the lead came in
  aggregatedb TEXT     -- aggregate database name

ODS Schema Mapping (Redshift)

SQL + Jinja2 Templates · Jarvis Analytics

With 14 different PMS schemas, we needed a unified data model — a single schema where "procedure" means the same thing regardless of which PMS the data came from. This is the ODS (Operational Data Store) layer: Jinja2-templated SQL that dynamically generates the right query for each PMS while outputting identical column names.

What's Jinja2 templating? Jinja2 is a template engine (like mail merge for code). Instead of writing 14 separate SQL files for 14 PMS systems, you write ONE template with {% if software == 'eaglesoft' %} blocks. At runtime, the system fills in the PMS name and generates the correct SQL. One template, 14 outputs — all producing the same columns.
📄 ods/_filters/procedures.sql — Universal procedure code mapping
SELECT
    proc.procedureid AS procedure_id,

    -- Eaglesoft sometimes stores procedure IDs instead of ADA codes
    {% if software == 'eaglesoft' %}
        COALESCE(proc.adacode, proc.procedureid) AS ada_code,
    {% else %}
        proc.adacode AS ada_code,
    {% endif %}

    -- Dentrix/Denterprise/Denticon: no category field — map via ADA code ranges
    -- OpenDental/Eaglesoft/others: have a built-in category field
    {% if software in ['dentrix', 'denterprise', 'denticon'] %}
        {% if proceduresCategory and proceduresCategory[0]|length > 2 %}
        CASE
        {% for i in range(0, proceduresCategory|length-1) %}
            WHEN (proc.adacode BETWEEN '{{ proceduresCategory[i][0] }}'
                                  AND '{{ proceduresCategory[i][1] }}')
            THEN '{{ proceduresCategory[i][2] }}'
        {% endfor %}
            ELSE 'Undefined'
        END AS type,
        {% else %}
            'Undefined' AS type,
        {% endif %}
    {% else %}
        proc.category AS type,       -- OpenDental, Eaglesoft etc. have this natively
    {% endif %}

    proc.description AS description
FROM procedurecodes proc
ORDER BY proc.adacode ASC
